# Execute NAV from a Prepared Rebuild Plan

NAV rebuilds will execute from one immutable, NAV-owned `NavRebuildPlan` containing the checkpoint state, ordered Transaction ledger entries, assets, Positive-holding intervals, and the range-loaded valuation data produced by `MarketData`. A successfully prepared plan guarantees that execution performs no database reads or fallback lookups; missing in-memory valuation data is an invariant failure. The first rollout will materialize the complete rebuild range because rstock is a personal CLI and the documented 100-asset, 20-year stress case is sufficient to measure its peak memory; windowed plans and concurrent write coordination are out of scope.

Preparation will require closing prices only during Positive-holding intervals and will treat transaction-date FX separately. It will preserve every Complete NAV snapshot in the contiguous calculable prefix, ending at the Effective valuation date immediately before the first blocking price or FX requirement. Generated output will be persisted in transactions bounded by both date and row targets, but one Complete NAV snapshot will never be split and may exceed the row target by itself. The existing normalized `portfolio_history` and `portfolio_asset_history` tables remain the aggregate and audit-detail representation of that atomic snapshot.

Routine readiness will trust the latest Complete NAV snapshot as the NAV rebuild checkpoint instead of replaying and auditing all earlier history. This trades automatic detection of legacy or manually introduced corruption for warm-readiness work proportional to new history; no explicit verification command or compatibility layer will block rollout for this personal application. Acceptance requires snapshot equivalence for existing calculable cases, zero database reads during plan execution, preparation query counts independent of rebuilt calendar dates and holding-days, interruption recovery from the last committed snapshot, and measured peak memory on the existing Criterion stress fixture. Once those gates pass, the prepared-plan engine will directly replace the current rebuild path without a feature flag or dual-engine period.
